NEKSUS CONTROL - FIRST SETUP

1. RENDER ENVIRONMENT VARIABLES
Keep your current DATABASE_URL, ADMIN_TOKEN, API_TOKEN, PORT, etc.
Add:
  CONTROL_ADMIN_USERNAME=choose-a-username
  CONTROL_ADMIN_PASSWORD=choose-a-strong-password
  CONTROL_ADMIN_NAME=NEKSUS Super Admin

2. DEPLOY BACKEND FIRST
Render settings remain:
  Root Directory: backend
  Build: go mod tidy && go build -o neksus-api .
  Start: ./neksus-api

Wait until Render is Live and verify:
  https://neksuseldv1.onrender.com/health

3. DEPLOY THE CONTROL PLATFORM AS A SECOND VERCEL PROJECT
Use the SAME GitHub repository, but create another Vercel project:
  Framework Preset: Other
  Root Directory: control
  Build Command: leave blank
  Output Directory: leave blank

You can later connect a domain such as control.neksus.eld.app.

4. LOGIN TO NEKSUS CONTROL
Use CONTROL_ADMIN_USERNAME and CONTROL_ADMIN_PASSWORD.
Create an Operator/Viewer/Manager and select the companies that account can access.

5. DEPLOY THE UPDATED ELD FRONTEND
Existing NEKSUS Vercel project:
  Root Directory: frontend

The NEKSUS ELD login screen now asks for the username/password created in NEKSUS Control.

6. CORS
If ALLOWED_ORIGINS is not '*', include BOTH the normal NEKSUS ELD domain and the new Control domain, comma-separated.

Example:
  ALLOWED_ORIGINS=https://neksus-eld.vercel.app,https://neksus-control.vercel.app

NOTE
ADMIN_TOKEN can remain on Render for maintenance/backward compatibility, but normal ELD operators no longer need or see it.
